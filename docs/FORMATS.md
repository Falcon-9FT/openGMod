# Форматы

Описания написаны по открытым источникам (Valve Developer Community wiki, вики GMod,
описания сообщества) и проверены на настоящих файлах. Все числа — little endian, строки — с
нулевым байтом в конце, если не сказано иное.

## VPK — паки Valve

Контент GMod и HL2 лежит в паках: `garrysmod/garrysmod_dir.vpk` и `sourceengine/hl2_*_dir.vpk`.
Пак состоит из файла-каталога `<имя>_dir.vpk` и файлов данных `<имя>_000.vpk`, `<имя>_001.vpk`
и так далее. Небольшой пак может держать данные в самом каталоге.

| Часть | Содержимое |
|---|---|
| заголовок v1 (12 байт) | `u32` сигнатура `0x55AA1234`, `u32` версия, `u32` размер дерева |
| заголовок v2 (28 байт) | v1 + `u32` размеры: встроенных данных, MD5 архивов, прочих MD5, подписи |
| дерево | расширения → папки → имена файлов, у каждого файла — запись |
| встроенные данные | байты файлов с индексом архива `0x7FFF` |

Дерево — три вложенных списка строк (расширение, папка, имя), каждый заканчивается пустой
строкой. Пробел `" "` значит «нет» (файл без расширения или в корне).

Запись файла:
* `u32` CRC-32 всего файла;
* `u16` число preload-байтов, которые идут сразу после записи;
* `u16` индекс архива (`0x7FFF` — сам каталог, отсчёт от конца дерева);
* `u32` смещение;
* `u32` длина;
* `u16` терминатор `0xFFFF`.

Файл — это его preload-байты, за которыми идут `длина` байт по `смещению` в своём архиве.

Реализация: `gmod-fs::vpk`. Проверена на тестовых паках ValvePak, собранных инструментами
Valve: многотомных, однофайловых, с preload, подписанных v2 из CS2.

## GMA — аддоны GMod

| Часть | Содержимое |
|---|---|
| заголовок | `"GMAD"`, `u8` версия формата (1–3) |
| | `u64` SteamID автора (не используется), `u64` время упаковки (Unix) |
| | версия ≥ 2: имена требуемого контента до пустой строки (на практике пусто) |
| | название, описание (в современных аддонах — JSON с `description`, `type`, `tags`), автор, `i32` версия аддона |
| список файлов | `u32` номер (1, 2, …; 0 — конец), путь, `i64` размер, `u32` CRC-32 |
| данные | байты файлов подряд в порядке списка |
| хвост | `u32` CRC-32 всего предыдущего (0, если упаковщик не считал) |

Реализация: `gmod-fs::gma` (чтение и запись). Обрезанный файл (оборванная загрузка) —
ошибка, а не «сколько успели прочитать».

## Воркшоп

* Подписки Steam хранит в `<библиотека>/steamapps/workshop/content/4000/<id>/`: там `.gma`
  или, у предметов из старого воркшопа, `<имя>_legacy.bin`.
* Список установленных — `steamapps/workshop/appworkshop_4000.acf` (KeyValues,
  `AppWorkshop/WorkshopItemsInstalled/<id>`). Папки предметов, которых в списке нет, не
  монтируются.
* `.bin` — это LZMA-поток в контейнере «alone» вокруг GMA:
  * 13 байт заголовка: байт свойств `(pb·5 + lp)·9 + lc`, `u32` размер словаря, `u64` размер
    распакованного (все единицы — неизвестен, тогда в конце стоит маркер);
  * затем сам поток.

  Декодер написан по спецификации LZMA SDK (public domain): `gmod-fs::lzma`. Распакованный
  GMA кладётся в `~/.opengmod/cache/workshop/<id>.gma` и используется, пока он не старше `.bin`.
* `garrysmod/cache/workshop/*.gma` — аддоны, которые скачали серверы. GMod монтирует их только
  на этих серверах, поэтому по умолчанию они не подключаются (`--server-downloads` в
  `gmod-check`).
* `garrysmod/addons/*.gma` — аддоны, положенные вручную.

## KeyValues

Текстовый формат Valve: `gameinfo.txt`, `.vmt`, скрипты в `scripts/`, VGUI `.res`,
локализация, `cfg/mount.cfg`, `.vdf` и `.acf` Steam. Правила токенизатора, как у движка:

* токен — строка в кавычках, `{`, `}` или последовательность символов до пробела, `"`, `{`, `}`;
* `//` — комментарий только там, где может начаться токен (`1//x` — один токен);
* escape-последовательности по умолчанию выключены: в материалах пути пишутся с `\`. Включены в
  файлах Steam и в локализации, где кавычки пишутся как `\"`;
* токен с `[` … `]` — условие для соседней пары (`[$WIN32]`, `[!$X360]`, `[$WINDOWS||$OSX]`).
  `$WIN32` означает любой ПК, консольные символы не определены;
* ключи сравниваются без учёта регистра ASCII и могут повторяться, порядок сохраняется;
* `#base` / `#include` на верхнем уровне — ссылки на другие файлы;
* NUL-байт заканчивает текст; UTF-16 с BOM (файлы локализации) декодируется;
* при ошибке движок закрывает текущий блок и читает дальше. Пустой ключ обрывает блок,
  ключ без значения получает пустую строку, а на верхнем уровне за ключом обязан идти `{`.

Не KeyValues, хотя и `.txt`: `scripts/sentences*.txt`, `scripts/hudanimations*.txt` (кроме
манифеста), `scripts/talker/*`, `scripts/dsp_presets.txt`, а также `.cfg` (это консольные
команды).

Реализация: `gmod-kv`.

## `gameinfo.txt` и `cfg/mount.cfg`

`GameInfo/FileSystem/SearchPaths` — строки вида `ids  путь`:
* `ids` — ID путей поиска через `+`;
* путь задаётся от папки установки, может начинаться с `|all_source_engine_paths|` (папка
  установки) или `|gameinfo_path|` (папка `gameinfo.txt`);
* `.vpk` на конце — пак по базовому имени (`garrysmod.vpk` → `garrysmod_dir.vpk`);
* `/*` на конце — каждая подпапка отдельно.

`cfg/mount.cfg` — `"mountcfg" { "<имя>" "<папка игры>" }`. Подключаются паки `*_dir.vpk` из
папки, затем сама папка.

Реализация: `gmod-fs::gameinfo`, порядок — `gmod-fs::mount` (см.
[ARCHITECTURE.md](ARCHITECTURE.md#файловая-система)).

## Диалект Lua в GMod

| GLua | Lua |
|---|---|
| `a != b` | `a ~= b` |
| `!a` | `not a` |
| `a && b`, `a \|\| b` | `a and b`, `a or b` |
| `// …`, `/* … */` | комментарии |
| `continue` | переход к следующей итерации цикла |

`continue` — оператор, только если сразу за ним кончается блок (`end`, `else`, `elseif`,
`until`, `;`). Иначе это обычное имя: `t.continue`, `local continue`, `goto continue`.

Как переводит `gmod-glua`:
* в `while` и `for` тело оборачивается в `do … end ::метка::`, а `continue` становится
  `goto метка`;
* в `repeat … until` метка ставится перед `until`. Здесь LuaJIT, как и с родным `continue`,
  не даёт перепрыгнуть объявление `local`.

Номера строк сохраняются, байты строк не меняются, BOM UTF-8 удаляется.
